## 1. 项目概述

### 1.1 项目背景

随着人工智能技术的发展，传统图文交互已经不能满足用户对自然、拟人化服务的期待。本项目属于"数字人服务系统"大课题中的子任务，目标是构建一个具备三维拟人化形象、能够进行自然语音交互的数字人交互系统，可应用于健康咨询、门诊预约、服务导览等场景。

项目拥有"对话 + 语音合成"的能力，展示层采用「可加载 VRM 三维模型」的方案，使数字人具备可更换的 3D 形象、口型同步与肢体动作能力。

### 1.2 项目目标

1. 支持加载标准 VRM 格式的三维虚拟人模型，并在网页端实时渲染。
2. 实现文本输入驱动的自然语言对话，并合成语音由数字人播报。
3. 实现语音与数字人嘴型（口型）、表情的同步联动，达到"数字人在说话"的效果。
4. 实现数字人的基础肢体动作（打招呼等）与拟人化微表情（自动眨眼、头部微动），并支持通过 .vrma 动作文件扩展肢体动作，可由对话关键词自动触发或手动加载播放。
5. 面向健康服务领域，提供健康咨询、预约挂号、服务咨询等基础业务问答能力。

### 1.3 适用范围

- 本系统为课程作业级演示版本，用于验证"三维数字人 + 语音交互"的完整技术链路。
- 当前对话采用内置规则式问答；系统预留了大语言模型（LLM）与语音识别（ASR）接口，便于后续升级。

## 2. 用户角色与使用场景

### 2.1 目标用户

| 角色 | 说明 |
|------|------|
| 普通用户 | 通过浏览器访问系统，与数字人进行文字/语音交互 |
| 系统维护者 | 准备数字人模型文件、部署与运维服务 |

### 2.2 典型使用场景

1. 健康咨询：用户输入"我最近头晕"，数字人给出作息、饮食等健康建议。
2. 预约挂号：用户输入"帮我预约挂号"，数字人引导用户选择科室与时间。
3. 服务咨询：用户询问可提供的服务项目，数字人进行介绍。
4. 形象展示：用户本地选择并加载任意 VRM 模型，观察数字人说话、眨眼、挥手等表现。用户还可加载 .vrma 动作文件，或通过对话关键词触发预设动作。

## 3. 功能需求

### 3.1 数字人形象加载（FR-01）

- 支持通过网页文件选择器加载本地 `.vrm` 模型文件。
- 模型加载完成后，自动适配相机视角并在页面居中展示。
- 加载过程中显示进度提示，加载失败给出明确错误提示。
- 支持多次更换模型，新模型加载后替换旧模型。
- 支持鼠标旋转、缩放查看模型（OrbitControls）。

**验收标准**：点击"选择模型"弹出文件选择框；选择有效 `.vrm` 后 3D 形象正常显示；选择无效文件时页面给出错误提示且不崩溃；可用鼠标拖动旋转、滚轮缩放查看模型。

### 3.2 语音交互与对话（FR-02）

- 提供文本框输入，用户输入问题后数字人以语音 + 文字两种方式回复。
- 回复文本按句子拆分，逐句合成语音并顺序播报。
- 当前提供规则式业务问答：问候、健康咨询、预约挂号、服务咨询、致谢等类别。

**验收标准**：用户输入"帮我预约挂号"后，页面展示回复文字，并顺序播放对应语音，语气通顺、无乱码。

### 3.3 口型与表情驱动（FR-03）

- 数字人播报语音时，嘴部随音频音量实时张合，形成口型同步效果。
- 数字人具备自动眨眼，周期约 2-5 秒随机。
- 说话期间伴有轻微点头，静默期间头部有自然的缓慢转动。

**验收标准**：播放语音期间，数字人嘴部明显随声音起伏张合；观察 5 秒以上可见规律眨眼。

### 3.4 肢体动作（FR-04）

- 提供"打招呼"按钮，触发数字人右侧手臂举起并挥动，约 2.6 秒后恢复。
- 支持 .vrma 动作文件：通过"播放动作"按钮手动选择本地 .vrma 文件，加载后循环播放。
- 支持对话关键词触发动作：当用户输入命中预设关键词时，系统自动加载并播放对应 .vrma 动作一次，播完恢复待机状态。

**验收标准**：点击"打招呼"后，数字人手臂平滑举起并摆动，随后自然复位；点击"播放动作"并选择有效 .vrma 后，数字人循环播放该动作；输入"你好"等关键词时，若对应动作文件存在则自动播放一次。

### 3.5 业务问答能力（FR-05）

系统内置规则问答，覆盖以下意图：

| 意图 | 触发关键词示例 | 系统响应 |
|------|--------------|---------|
| 问候 | 你好 / 您好 / 在吗 | 自我介绍并引导用户 |
| 预约挂号 | 预约 / 挂号 / 门诊 | 引导选择科室与时间 |
| 健康咨询 | 不舒服 / 头晕 / 血压 / 失眠 | 给出作息饮食建议 |
| 服务咨询 | 服务 / 咨询 / 项目 | 介绍可提供的服务 |
| 致谢 | 谢谢 / 感谢 | 礼貌回应 |

### 3.6 动作文件管理（FR-06）

- 系统维护一个动作文件目录（`vrm_demo/static/animations/`），用于存放 `.vrma` 格式的动作文件。
- 动作文件命名与对话关键词通过配置表（`ACTION_RULES`）映射，当前预置四类动作：greet（问候）、booking（预约）、thanks（致谢）、explain（健康咨询）。
- 动作文件缺失不影响对话与语音播报，仅在浏览器控制台提示"动作文件未找到"。

**验收标准**：将符合命名规则的 .vrma 文件放入动作目录后，输入对应关键词可触发该动作播放；目录为空时对话功能正常，不报错。

## 4. 非功能需求

### 4.1 性能

- 模型资源通过 CDN 按需加载，静态资源采用缓存策略，首屏加载时间在可接受范围内。
- 口型驱动采用轻量级音频能量分析，渲染帧率应保持流畅（依赖硬件 WebGL 能力）。

### 4.2 兼容性

- 后端运行于 Python 3.12 环境（Windows 已验证）。
- 前端基于现代浏览器，需支持 ES Module 与 Import Map（Chrome/Edge 89+、Safari 16.4+、Firefox 108+）。
- 静态资源 MIME 类型必须正确（JS 使用 `text/javascript`），否则浏览器拒绝执行模块。

### 4.3 可扩展性

- 对话逻辑与语音合成解耦：`llm_reply` 可替换为大模型接口，TTS 可替换为其他合成引擎。
- 口型驱动与模型渲染解耦：更换 VRM 模型无需修改代码。
- 动作触发规则可配置：`ACTION_RULES` 可扩展关键词与动作名的映射，动作文件按命名约定放入目录即生效。

### 4.4 安全性

- 数字人模型与对话内容均来自本地或受信来源，无敏感信息采集。
- 系统仅监听本机默认端口，用于课程演示，未暴露公网。

## 6. 验收标准汇总

1. 系统能正常启动，浏览器访问页面无报错。
2. 可加载本地 VRM 模型并正确渲染，支持鼠标旋转缩放查看。
3. 输入文本后，数字人以正确文本回复并同步播报语音、驱动口型。
4. 数字人具备自动眨眼与"打招呼"动作。
5. 健康咨询、预约、服务咨询等意图能正确回应。
6. 可通过"播放动作"按钮手动加载 .vrma 动作文件并循环播放。
7. 输入命中预设关键词时，若对应 .vrma 动作文件存在，数字人自动播放该动作一次。

## 7. 术语表

| 术语 | 说明 |
|------|------|
| VRM | 日本发布的开放三维虚拟人模型格式（VRoid 等工具导出） |
| 数字人 | 基于计算机图形与人工智能技术构建的虚拟人形象 |
| TTS | Text-to-Speech，语音合成 |
| BlendShape | 三维模型的形变混合，用于表现口型与表情 |
| WebGL | 浏览器 3D 渲染标准 |
| edge-tts | 基于微软 Azure 语音服务的免费在线语音合成库 |
| .vrma | VRM Animation 格式，VRM 模型的动作/动画文件 |
| AnimationMixer | Three.js 的动画混合器，用于播放与管理 AnimationClip |
