## 1. 项目概述

### 1.1 项目背景

随着人工智能与计算机图形学技术的快速发展，传统图文交互已难以满足用户对自然、拟人化服务的期待。语音交互与三维虚拟人的结合，成为新一代人机交互的重要方向，在健康咨询、智慧服务、在线导览等领域具有广阔的应用前景。

本项目是"数字人服务系统"大课题下的子任务。本项目拥有"对话 + 语音合成"的服务能力，展示层采用「Three.js + three-vrm 三维渲染」的方案，使数字人具备可更换的 3D 形象、口型同步与肢体动作能力。

### 1.2 项目定位

- **项目性质**：课程作业级演示项目，用于验证"三维数字人 + 语音交互"的完整技术链路。
- **应用场景**：健康咨询、门诊预约、服务导览等健康服务领域。
- **核心价值**：以较低成本实现可更换形象、口型同步、肢体动作的拟人化数字人，为后续接入大语言模型（LLM）与语音识别（ASR）预留升级空间。

### 1.3 立项依据

1. 技术上，VRM 开放格式 + Three.js 渲染 + 免费 TTS 的组合成熟可行，无需昂贵设备即可完成原型。
2. 需求上，拟人化数字人在服务行业有明确的应用与展示价值。

## 2. 项目目标与范围

### 2.1 总体目标

构建一个可在浏览器端运行的拟人化数字人交互系统，实现"加载三维模型 → 文本对话 → 语音合成播报 → 口型与肢体动作联动"的完整闭环。

### 2.2 具体目标

| 编号 | 目标 | 对应功能需求 |
|------|------|-------------|
| G1 | 支持加载标准 VRM 三维模型并实时渲染，鼠标旋转缩放查看 | FR-01 |
| G2 | 实现文本驱动的自然语言对话与逐句语音播报 | FR-02 |
| G3 | 实现语音与数字人嘴型、表情的同步联动 | FR-03 |
| G4 | 实现基础肢体动作与拟人化微表情，支持 .vrma 动作文件 | FR-04 / FR-06 |
| G5 | 面向健康服务领域提供基础业务问答能力 | FR-05 |

（功能需求编号与《需求定义书》保持一致。）

### 2.3 范围边界

**项目内（In Scope）**：

- VRM 模型本地加载与三维渲染
- 规则式对话 + edge-tts 语音合成
- 音量驱动的口型同步、自动眨眼、头部微动、挥手动作
- .vrma 动作文件的加载、关键词自动触发与手动播放
- 基于 FastAPI 的对话接口与静态资源托管

**项目外（Out of Scope）**：

- 大语言模型接入（当前为规则问答，仅预留接口）
- 语音识别（ASR）输入（当前仅文本输入）
- 公网部署与多用户并发支持（仅本机演示）
- 移动端适配与多语言国际化

## 3. 项目可行性分析

### 3.1 技术可行性

| 维度 | 分析 |
|------|------|
| 渲染 | Three.js 0.180.0 + @pixiv/three-vrm 3.5.5 成熟稳定，生态完善，官方文档齐全 |
| 语音 | edge-tts 基于微软 Azure 神经网络语音，在线免费、中文音色自然，无需本地模型或 GPU |
| 动作 | VRMAnimationLoaderPlugin + AnimationMixer 支持 .vrma 动作文件加载与播放 |
| 服务端 | FastAPI 异步、类型友好，自带静态文件托管，适合轻量原型 |
| 风险点 | 依赖 CDN 在线资源与 edge-tts 在线服务，需保持网络连通；已通过本地 MIME 类型修复解决 .js 加载问题 |

**结论**：技术路径可行，核心链路已在 Windows 环境验证通过。

### 3.2 资源可行性

- 硬件：普通 PC 即可运行（渲染依赖浏览器 WebGL 能力）。
- 软件：Python 3.12（Anaconda）及 fastapi、uvicorn、pydantic、edge-tts 等依赖，均可免费获取。
- 素材：VRM 模型与 .vrma 动作文件可来自开源资源或 Blender/VRoid 制作。

**结论**：所需资源均可免费获取，无额外成本。

### 3.3 时间可行性

项目各功能模块解耦清晰，可并行开发与迭代；基于开源项目二次开发复用了对话与语音流程，整体工作量可控。

**结论**：在课程周期内可完成全部预定目标。

## 4. 技术方案概要

### 4.1 系统架构

系统采用前后端分离的 B/S 架构，服务端轻量化，仅负责对话与语音合成，三维渲染与口型驱动全部在浏览器端完成。

```text
浏览器端（Three.js + three-vrm）
  ├── 页面 UI 层（HTML/CSS）
  ├── 渲染与动画层（VRM 渲染 / 口型 / 眨眼 / 动作）
  └── 交互逻辑层（HTTP 请求 / 音频解码 / 音量分析 / 队列播放）
        │  HTTP (JSON) + 静态资源
服务端（FastAPI + Uvicorn）
  ├── /static/*   静态页面与脚本托管
  └── /api/chat   对话 + 动作匹配 + 语音合成接口
```

### 4.2 技术选型

| 层次 | 技术 |
|------|------|
| 前端语言 | HTML5 / CSS3 / JavaScript (ES6+) |
| 模块化 | ES Module + Import Map（CDN 免构建） |
| 3D 渲染 | Three.js 0.180.0 |
| 模型加载 | @pixiv/three-vrm 3.5.5（含 VRMAnimationLoaderPlugin） |
| 相机控制 | OrbitControls |
| 音频处理 | Web Audio API（AnalyserNode） |
| 后端框架 | FastAPI + Uvicorn |
| 语音合成 | edge-tts |

### 4.3 关键技术点

1. **音量驱动口型**：通过 AnalyserNode 获取实时音频能量（RMS），映射为嘴部开合度，并轮换元音口型（aa / ih / ou / ee / oh），形成自然的"说话感"。
2. **拟人化微表情**：自动眨眼（睁眼 2.2~4.8s + 闭眼 240ms）、静默头部缓慢摆动、说话轻微点头。
3. **动作触发机制**：后端 `ACTION_RULES` 规则表 + `match_action` 匹配关键词，前端 `playActionByName` 按动作名加载 `animations/{name}.vrma` 播放一次；同时提供手动加载 .vrma 循环播放。

## 7. 风险分析与应对

| 风险 | 影响 | 应对措施 |
|------|------|---------|
| 依赖在线资源（CDN / edge-tts）不可用 | 页面或语音功能异常 | 依赖固定版本；必要时本地化依赖与降级提示 |
| .js 被浏览器以错误 MIME 缓存 | 页面按钮无响应 | 服务端显式注册 text/javascript；强制刷新 |
| 动作文件缺失或命名错误 | 关键词触发无动作 | 动作缺失不影响对话，仅提示"文件未找到"；提供命名约定说明 |
| 模型兼容性问题 | 个别 VRM 显示异常 | 表情设置采用 try/catch 容错；加载失败给出提示 |
| 多解释器环境冲突 | 依赖装错解释器 | 文档明确使用实际安装依赖的解释器 |
